# 现有效果保护优先的后台低代码落地说明

## 1. 编写目的

本说明用于统一项目下一阶段的改造方向：在尽量保留当前前端展示效果的基础上，把后台资料采集、审核、发布和质量检查流程做得更规范、更易维护。

当前项目已经具备学校门户、系部门户、创新育人专题、专题卡片、资料抽屉、图片轮播、二维码详情页等较成熟的展示效果。因此，本阶段不建议重做前台，也不建议把系统改成通用页面搭建器。

推荐路线是：

```text
前台展示效果固定
后台资料模板可配置
教师按模板填报
管理员审核发布
系统自动映射到展示数据
```

一句话概括：

> 低代码用于后台业务资料采集，不用于自由拖拽前台页面。

## 2. 产品原则

### 2.1 保留现有效果

现阶段前台已经形成了可用的视觉方向，尤其是以下页面和交互不应被大改：

- 欢迎页。
- 学校门户页。
- 系部门户页。
- 创新育人专题页。
- 专题卡片展示。
- 资料抽屉详情。
- 图片原比例轮播。
- 扫码详情页。
- 顶部统一导航栏。

后续优化重点应放在内容质量、资料结构、后台管理逻辑和展示稳定性上，而不是重新设计整套前端。

### 2.2 后台降低录入门槛

教师和系部管理员不应该理解页面结构，也不应该自己调整前端样式。他们只需要完成三件事：

- 选择资料所属专题和板块。
- 按模板填写文字、图片、视频、附件。
- 提交审核。

页面如何展示，由系统根据资料类型和现有展示模板自动决定。

### 2.3 管理员控制标准

管理员的工作重点不是逐条手动改前台数据，而是维护标准：

- 配置资料采集模板。
- 固定专题板块。
- 设置必填项和资料规范。
- 审核资料是否合格。
- 发布到前台展示。
- 查看质量检查和缺项报告。

## 3. 页面逻辑梳理

### 3.1 学校门户

学校门户是总入口，负责展示学校整体形象和重点专题。

建议保留内容：

- 学校概况。
- 创新育人专题入口。
- 系部门户入口。
- 重点成果。
- 学校官网二维码。

学校官网二维码只在欢迎页和学校门户页展示，其他页面不再重复展示，避免页面拥挤。

### 3.2 系部门户

系部门户展示单个系部的整体风貌，顶部栏统一使用 `http://127.0.0.1:8000/display` 的视觉样式。

顶部栏建议规则：

- 左侧放校徽。
- 不重复放“毕节职业技术学院”大字。
- 中间或右侧展示当前系部名称。
- 当前系部名称支持下拉切换到其他系部。
- 返回逻辑使用当前页面内跳转或重定向，不反复打开新页面。

系部门户内容建议包括：

- 系部概况。
- 专业建设。
- 实训条件。
- 师资队伍。
- 学生风采。
- 产教融合。
- 荣誉成果。
- 视频资源。

### 3.3 创新育人专题

创新育人专题与院系风采融合，不再做两套平行内容。

专题固定为以下板块：

- 现代农业。
- 数字文旅。
- 智慧康养。
- 财经商贸。
- 数智技术。
- 智慧能源。
- 智能制造。
- 同心校园文化。

注意：前期讨论中“财经商贸”出现过两次，落地时建议只保留一个“财经商贸”，避免后台统计和前台导航重复。

每个系部可以被归入一个或多个专题板块，但前台展示仍保持统一样式。

### 3.4 专题下的固定栏目

专题进入后，内容栏目建议固定为：

- 专题概况。
- 专业群布局。
- 实训场景。
- 产教协同。
- 名师名匠。
- 优秀校友。
- 优秀学生。
- 专题成果。
- 技能大赛。
- 荣誉资质。
- 视频资源。

这些栏目作为后台模板和前台展示的稳定基础。后续如果新增栏目，应通过管理员配置扩展，但第一阶段不建议频繁增加。

## 4. 资料抽屉展示规则

资料抽屉是当前展示体验的核心，应重点解决“图片数量不固定、文字长短不固定、不同图片尺寸显示不全”的问题。

### 4.1 抽屉基本规则

- 抽屉内容整体可滚动。
- 抽屉打开后保留自动循环滚动能力。
- 图片不裁剪，优先按原图比例缩放。
- 图片区域只展示一张主图。
- 多张图片按时间或排序自动轮播。
- 文字和图片保持协调，不因图片尺寸变化挤压布局。
- 详情页可复用 `/display?project=15&code=BJ-TEACHER&source=expo-admin` 的信息结构，但去掉左侧大图样式。

### 4.2 图片展示规则

不同资料图片数量不固定，建议统一为：

```text
右侧图片区域 = 单图展示 + 原比例缩放 + 自动轮播
```

具体规则：

- 只有 1 张图：显示该图，按容器完整缩放。
- 有多张图：每次显示 1 张，自动轮播下一张。
- 图片很宽：宽度适配，垂直方向居中。
- 图片很高：高度适配，水平方向居中。
- 图片太小：不强行拉伸到失真，可加柔和背景承托。
- 不使用 `cover` 裁剪主体内容。

这样可以兼容后台上传数量不确定、比例不统一的情况。

### 4.3 文字展示规则

文字量也不固定，建议按资料类型决定排版：

- 人物类：图片与简介并列，突出姓名、身份、荣誉、简介。
- 活动类：先展示标题、时间、地点、摘要，再展示正文和图片轮播。
- 荣誉类：突出奖项名称、获奖单位、获奖时间、证明材料。
- 成果类：突出成果名称、所属板块、建设成效、支撑材料。
- 视频类：优先展示视频，文字作为说明。

如果文字过长，抽屉正文区域滚动，不挤压顶部标题和右侧图片。

## 5. 后台低代码能力定位

后台低代码能力不做“页面搭建器”，而做“资料采集模板”。

### 5.1 管理员可配置内容

管理员可以配置：

- 模板名称。
- 模板编码。
- 所属门户。
- 所属专题。
- 所属栏目。
- 资料类型。
- 字段列表。
- 必填规则。
- 上传规则。
- 字段提示语。
- 前台映射规则。
- 是否启用。

### 5.2 教师填报内容

教师只看到简化后的填报页面：

- 标题。
- 摘要。
- 正文。
- 图片。
- 视频。
- 附件。
- 人物信息。
- 荣誉信息。
- 关联专题。
- 提交审核。

教师不接触 CSS、不接触布局、不接触数据库字段。

### 5.3 审核发布逻辑

资料生命周期建议为：

```text
草稿
  -> 提交审核
  -> 待审核
  -> 通过 / 退回
  -> 发布
  -> 前台展示
```

退回后，教师可以修改并重新提交。管理员提交的资料可以按权限设置为直接发布或仍需审核。

## 6. 数据结构建议

为了保护现有前台，建议继续让 `content_items` 作为前台最终读取的数据源。

后台低代码数据可以分为三层：

```text
lowcode_forms      资料采集模板
lowcode_records    教师填报记录
content_items      前台展示内容
```

关系如下：

```text
管理员配置 lowcode_forms
教师填写 lowcode_records
审核通过后生成或更新 content_items
前台页面继续读取 content_items
```

这样前台不用大改，后台也能逐步规范化。

## 7. 权限角色建议

### 7.1 超级管理员

- 管理所有门户。
- 管理所有模板。
- 审核所有资料。
- 管理用户和角色。
- 查看质量报告。
- 导出验收资料。

### 7.2 系部管理员

- 管理本系部资料。
- 审核本系部教师提交内容。
- 查看本系部质量报告。
- 不能修改全局系统配置。
- 不能管理其他系部资料。

### 7.3 教师

- 按模板填报资料。
- 保存草稿。
- 提交审核。
- 查看退回原因。
- 修改后重新提交。

## 8. 后台菜单建议

后台建议按业务流程重新组织：

```text
首页概览
  -> 待处理事项
  -> 资料完整度
  -> 最近更新

门户管理
  -> 学校门户
  -> 系部门户
  -> 创新育人专题

资料采集模板
  -> 模板列表
  -> 新建模板
  -> 导入模板
  -> 导出模板
  -> 模板质量检查

资料填报
  -> 新建填报
  -> 我的草稿
  -> 我的提交
  -> 退回修改

资料审核
  -> 待审核
  -> 已通过
  -> 已退回
  -> 已发布

素材管理
  -> 图片
  -> 视频
  -> 附件
  -> 素材归档

质量检查
  -> 内容完整度
  -> 板块覆盖率
  -> 图片缺失
  -> 附件缺失
  -> 模板质量
```

## 9. 实施阶段

### 9.1 第一阶段：稳定现有效果

目标：先稳住前台，不让现有页面继续变乱。

工作内容：

- 统一顶部栏。
- 修正返回时重复打开新页面的问题。
- 优化系部下拉切换。
- 保持学校官网二维码只在欢迎页和学校门户页出现。
- 抽屉内容支持滚动。
- 图片统一原比例缩放和单图轮播。
- 专题栏目固定。

验收标准：

- 页面不重叠。
- 图片不被裁剪主体。
- 不同屏幕尺寸下布局稳定。
- 返回和切换逻辑符合预期。

### 9.2 第二阶段：后台资料模板化

目标：让资料录入从“手工维护数据”变成“按模板填报”。

工作内容：

- 建立固定专题模板。
- 建立资料类型模板。
- 支持字段配置。
- 支持图片、视频、附件上传。
- 支持草稿、提交、退回、重提。
- 审核通过后自动写入 `content_items`。

验收标准：

- 教师可以不懂前端也能提交资料。
- 管理员可以通过模板规范资料。
- 前台能读取审核后的内容。

### 9.3 第三阶段：质量检查和验收导出

目标：让管理员知道哪些资料缺失、哪些模板不完整、哪些板块还没覆盖。

工作内容：

- 内容质量报告。
- 素材归档报告。
- 低代码填报进度报告。
- 模板质量报告。
- CSV 导出。
- 验收资料导出。

验收标准：

- 能看出每个专题资料是否完整。
- 能看出每个模板是否符合规范。
- 能导出检查结果用于整理和汇报。

## 10. 工程难度评估

整体难度为中等，主要原因是当前项目已经有较完整的前台页面和基础后台，不需要从零开发。

### 10.1 难度较低

- 顶部栏统一。
- 二维码展示范围控制。
- 固定专题栏目。
- 图片轮播展示。
- 抽屉滚动。
- CSV 导出。
- 后台菜单整理。

### 10.2 难度中等

- 资料模板字段配置。
- 草稿和审核流程。
- 低代码记录映射到 `content_items`。
- 系部管理员权限隔离。
- 模板质量检查。
- 内容完整度统计。

### 10.3 不建议第一阶段做

- 自由拖拽页面。
- 自定义 CSS。
- 自定义数据库建表。
- 复杂流程引擎。
- 多租户系统。
- 大规模重构前端页面。

## 11. 风险控制

### 11.1 前端风险

风险：为了适配后台模板而重写前端，导致当前展示效果被破坏。

控制方式：

- 前台继续读取 `content_items`。
- 后台负责生成结构化内容。
- 页面样式只做局部优化，不整体推翻。

### 11.2 数据风险

风险：上传资料来源多、命名乱、图片比例不统一。

控制方式：

- 后台模板增加字段提示。
- 上传文件自动归档。
- 图片展示用原比例缩放。
- 管理端增加素材缺失和异常检查。

### 11.3 使用风险

风险：教师觉得后台复杂，不愿意填。

控制方式：

- 教师端只显示填报所需字段。
- 不展示模板配置项。
- 支持草稿保存。
- 退回原因清晰可见。

## 12. 仓库和素材管理约定

大素材不进入 Git 仓库。

建议约定：

- `uploads/` 中的大图片、视频、附件走网盘或本地部署目录。
- Git 仓库只保存代码、脚本、文档、必要的小型配置。
- 数据库可以按需要单独提交最新样本，但要避免把大型素材一起带入仓库。
- 开发阶段不打包，不执行生产构建。
- 当前工作继续基于 `1.1` 分支。

## 13. 推荐落地结论

本项目最适合的改造方式是：

```text
保持前台统一展示
固定专题和栏目
后台做资料采集模板
教师按模板填报
管理员审核发布
系统自动生成展示内容
质量报告辅助验收
```

这样既能满足“低代码快速开发业务功能”的要求，又不会破坏现在已经做出来的页面效果。后续开发应优先保证展示稳定、资料规范、后台流程清晰，再逐步扩展模板配置能力。
