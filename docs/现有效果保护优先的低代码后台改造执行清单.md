# 现有效果保护优先的低代码后台改造执行清单

## 1. 核心结论

当前项目不建议改造成“通用低代码页面搭建平台”，更适合改造成“资料采集模板 + 审核发布 + 展示数据生成”的后台业务系统。

一句话原则：

> 前台展示效果尽量不推翻，低代码能力主要服务后台资料填报、审核、发布和质量检查。

这样做的好处是：保留目前已经做出来的学校门户、系部门户、创新育人专题、卡片、抽屉、轮播、二维码详情页等展示效果，同时让后台资料上传和管理更规范。

## 2. 改造边界

### 2.1 本阶段要做

- 统一后台资料采集模板。
- 固定创新育人专题和专题下栏目。
- 教师按模板填写资料，不接触页面样式。
- 系部管理员审核本系部资料。
- 超级管理员维护模板、栏目、质量规则和发布。
- 审核通过后自动生成或更新前台展示数据。
- 前台继续读取 `content_items` 或现有结构化展示数据。
- 图片按原比例缩放，支持单图展示和多图自动轮播。
- 抽屉详情支持滚动，避免图片和文字互相挤压。
- 质量报告用于检查缺图、缺字段、缺栏目和未发布内容。

### 2.2 本阶段暂不做

- 不做自由拖拽页面搭建器。
- 不允许普通教师修改前台布局。
- 不允许普通教师配置 CSS。
- 不做万能数据库建表器。
- 不做复杂流程引擎。
- 不重写当前前台展示页面。
- 不把 `uploads/` 大素材提交到 GitHub。
- 开发阶段不打包、不做生产构建。

## 3. 页面逻辑

### 3.1 欢迎页

定位：大屏或入口欢迎页面。

保留内容：

- 学校视觉入口。
- 进入学校门户。
- 学校官网二维码。

二维码规则：

- 欢迎页可以展示学校官网二维码。
- 其他专题页、系部门户页不重复展示学校官网二维码。

### 3.2 学校门户页

定位：全校总门户。

保留内容：

- 学校整体形象。
- 创新育人专题入口。
- 系部门户入口。
- 重点成果展示。
- 学校官网二维码。

顶部栏：

- 统一使用 `/display` 的顶部栏风格。
- 放校徽。
- 不在顶部重复放大号“毕节职业技术学院”文字。

### 3.3 系部门户页

定位：展示单个系部整体风貌。

顶部栏规则：

- 统一 `/display` 顶部栏样式。
- 左侧放校徽。
- 当前系部名称支持下拉切换。
- 返回时使用当前页面内跳转或重定向，不重复打开新页面。

内容建议：

- 系部概况。
- 专业建设。
- 实训条件。
- 师资队伍。
- 学生风采。
- 产教融合。
- 荣誉成果。
- 视频资源。

### 3.4 创新育人专题页

定位：把院系风采和创新育人专题融合展示。

专题固定为：

- 现代农业。
- 数字文旅。
- 智慧康养。
- 财经商贸。
- 数智技术。
- 智慧能源。
- 智能制造。
- 同心校园文化。

说明：

- 前期讨论中“财经商贸”出现过重复，落地时只保留一个。
- 一个系部可以归入一个或多个专题。
- 前台展示仍保持统一视觉，不因为归属变化重新设计页面。

## 4. 专题栏目模板

专题下栏目固定为以下 11 类：

| 顺序 | 栏目 | 建议 key | 用途 |
|---:|---|---|---|
| 1 | 专题概况 | overview | 专题背景、建设目标、整体介绍 |
| 2 | 专业群布局 | majors | 专业设置、课程体系、人才培养方向 |
| 3 | 实训场景 | training | 实训室、基地、设备、教学场景 |
| 4 | 产教协同 | cooperation | 校企合作、订单班、共同体、项目合作 |
| 5 | 名师名匠 | masters | 教学名师、技能大师、教师团队 |
| 6 | 优秀校友 | alumni | 校友人物、就业成果、成长故事 |
| 7 | 优秀学生 | students | 学生人物、竞赛经历、成长案例 |
| 8 | 专题成果 | achievements | 教学成果、项目成果、建设成效 |
| 9 | 技能大赛 | competitions | 赛事、获奖、承办活动 |
| 10 | 荣誉资质 | honors | 证书、奖项、资质认定 |
| 11 | 视频资源 | media | 宣传片、访谈、纪实视频 |

后台模板和前台栏目都围绕这 11 类组织，第一阶段不频繁新增栏目。

## 5. 资料类型模板

为了适配不同内容量和图片数量，资料类型建议固定为以下几类：

| 类型 | key | 展示策略 |
|---|---|---|
| 普通图文 | article | 标题、摘要、正文、图片轮播 |
| 人物 | person | 图片与人物简介并列，突出姓名、身份、荣誉 |
| 活动 | activity | 标题、时间地点、摘要、正文、图片轮播 |
| 荣誉 | honor | 突出奖项、获奖单位、时间、证书图片 |
| 成果 | achievement | 突出成果名称、建设成效、支撑材料 |
| 场景 | scene | 突出实训空间、设备、教学场景图片 |
| 视频 | video | 优先展示视频，文字作为说明 |

后台上传资料时选择资料类型，前台根据类型自动套用对应展示策略。

## 6. 图片和文字展示规则

### 6.1 图片

- 不使用强裁剪作为默认策略。
- 优先按原图比例完整缩放。
- 右侧图片区域每次只展示一张图。
- 多张图片按排序或上传时间自动轮播。
- 宽图水平适配，高度居中。
- 长图高度适配，水平居中。
- 图片过小不强行拉伸到失真，可以使用柔和背景承托。
- 后台不要求上传图片比例完全一致。

### 6.2 文字

- 标题、摘要、正文分层显示。
- 长正文在抽屉内容区内滚动。
- 标题区和关闭按钮不被正文挤压。
- 人物类内容让简介靠近人物图片。
- 活动类内容先呈现基本信息，再展示正文和图片。
- 荣誉类内容突出奖项和证书。

## 7. 后台角色权限

### 7.1 超级管理员

- 管理所有门户。
- 管理所有专题和栏目。
- 配置资料采集模板。
- 审核和发布全部资料。
- 查看质量报告。
- 导出验收资料。
- 管理用户和权限。

### 7.2 系部管理员

- 管理本系部资料。
- 审核本系部教师提交的资料。
- 查看本系部质量报告。
- 不能修改全局模板。
- 不能管理其他系部资料。

### 7.3 教师

- 按模板填写资料。
- 保存草稿。
- 提交审核。
- 查看退回原因。
- 修改后重新提交。
- 不配置模板。
- 不查看管理报表。
- 不直接修改前台展示数据。

## 8. 后台菜单建议

后台菜单按业务流程组织：

```text
首页概览
  -> 待处理事项
  -> 最近更新
  -> 资料完整度

门户管理
  -> 学校门户
  -> 系部门户
  -> 创新育人专题

资料采集模板
  -> 模板列表
  -> 新建模板
  -> 模板质量检查

资料填报
  -> 新建填报
  -> 我的草稿
  -> 我的提交
  -> 退回修改

资料审核
  -> 待审核
  -> 已通过
  -> 已退回
  -> 已发布

素材管理
  -> 图片
  -> 视频
  -> 附件
  -> 素材归档

质量检查
  -> 内容完整度
  -> 板块覆盖率
  -> 图片缺失
  -> 附件缺失
  -> 模板质量
```

## 9. 数据结构方向

继续让 `content_items` 作为前台最终展示数据源。

建议数据流：

```text
lowcode_forms
  管理员维护资料采集模板

lowcode_records
  教师按模板填写并提交资料

content_items
  审核通过后生成或更新前台展示内容
```

这样可以保护现有前台页面，同时让后台资料逐步规范化。

## 10. 实施顺序

### 第一阶段：稳住展示效果

- 统一顶部栏。
- 控制二维码只在欢迎页和学校门户页展示。
- 修复返回时重复打开新页面的问题。
- 固定专题和栏目。
- 优化抽屉滚动。
- 优化图片原比例展示和轮播。
- 保证不同屏幕尺寸不重叠。

验收标准：

- 页面元素不重叠。
- 图片主体不被裁掉。
- 抽屉内容可以滚动。
- 多图可以自动轮播。
- 返回和切换逻辑符合预期。

### 第二阶段：后台模板化

- 固定 11 个专题栏目。
- 建立资料类型模板。
- 管理员配置字段和必填项。
- 教师只看到填报表单。
- 支持草稿、提交、退回、重提。
- 审核通过后生成展示数据。

验收标准：

- 教师不需要理解页面布局也能提交资料。
- 管理员可以通过模板规范资料。
- 前台可以读取审核后的内容。

### 第三阶段：质量检查和验收导出

- 内容完整度检查。
- 栏目覆盖率检查。
- 图片和附件缺失检查。
- 模板质量检查。
- 支持 CSV 或验收资料导出。

验收标准：

- 能看出每个专题哪些栏目缺资料。
- 能看出哪些资料缺图片或关键字段。
- 能导出给学校或项目验收使用的检查结果。

## 11. 风险控制

### 11.1 前台风险

风险：为了适配后台模板，过度改动前台，导致当前视觉效果被破坏。

控制：

- 前台继续读取稳定结构。
- 后台负责生成结构化数据。
- 只做局部适配，不整体重写。

### 11.2 数据风险

风险：上传资料来源复杂，图片比例和文字量不统一。

控制：

- 用资料类型模板约束字段。
- 图片展示采用原比例缩放和轮播。
- 后台增加缺失检查。
- 素材归档和展示数据分离。

### 11.3 使用风险

风险：教师觉得后台太复杂，不愿意填。

控制：

- 教师端只显示填报、草稿、提交、退回修改。
- 不显示模板配置、质量报表和结构化数据编辑。
- 退回原因清楚可见。

## 12. Git 和素材约定

- 当前开发基于 `1.1` 分支。
- GitHub 仓库只提交代码、文档、脚本、结构化小数据和必要数据库快照。
- `uploads/` 大素材不提交 GitHub，走网盘或本地部署目录。
- 最新数据库可以按需要放一份到 `database/expo-latest.db`。
- 开发阶段不打包。

## 13. 最终目标

最终要形成的系统逻辑是：

```text
学校门户和系部门户负责展示
创新育人专题负责组织内容
后台模板负责规范采集
教师负责按模板填报
管理员负责审核发布
系统负责生成前台展示数据
质量报告负责验收检查
```

这条路线改造量可控，也最能保护目前已经做出来的展示效果。
