# 低代码资料模板改造方案

## 1. 改造目标

本次改造的目标不是把系统改成通用低代码平台，而是在现有展厅系统基础上增加一层“低代码资料模板能力”，让管理员和老师可以更快、更规范地录入业务资料。

核心原则：

- 不推倒现有前台展示效果。
- 不开放前台自由拖拽排版。
- 不替换现有 `content_items` 结构化资料体系。
- 不破坏现有专题页、系部门户页、抽屉详情页和图片轮播样式。
- 低代码能力主要发生在后台，用于规范表单、字段、校验和资料映射。

最终形成的流程：

```text
管理员配置资料模板
        ↓
老师按模板填写资料
        ↓
系统生成结构化资料 content_item
        ↓
进入审核/发布流程
        ↓
前台继续按现有卡片、专题滚动、抽屉模板展示
```

## 2. 当前系统基础

项目目前已经具备低代码改造的基础，不需要从零开始。

已有能力：

- 学校门户、系部门户、专题门户的分层展示。
- 创新育人专题 11 个固定板块。
- 结构化资料 `content_items`。
- 图片/视频素材管理。
- 审核、发布、删除申请等基础流程。
- 前台专题卡片无缝循环滚动。
- 抽屉详情页支持人物、荣誉、视频等差异化排版。
- 后台已有结构化资料录入表单。

因此低代码改造应当是“增强后台资料录入”，而不是重做展示系统。

## 3. 产品定位

建议将该能力命名为：

- 资料采集模板
- 业务资料模板
- 智能资料表单
- 低代码资料模板

推荐使用名称：**资料采集模板**。

原因：

- 比“低代码平台”更贴近老师和管理员的理解。
- 避免用户误以为可以自由设计前台页面。
- 突出它的真实价值：规范资料上传、减少重复录入、自动适配展示。

## 4. 功能边界

### 4.1 做什么

第一阶段建议支持：

- 管理员创建资料模板。
- 模板可选择绑定资料类型。
- 模板可配置字段。
- 字段可设置必填、提示、默认值、排序。
- 老师按模板填写资料。
- 表单提交后自动生成 `content_item`。
- 图片、视频按角色进入素材数组。
- 提交后复用现有审核发布流程。
- 前台继续使用现有展示模板。

### 4.2 不做什么

第一阶段明确不做：

- 不做前台页面自由拖拽。
- 不做万能低代码页面搭建器。
- 不做动态数据库建表。
- 不做复杂公式引擎。
- 不做复杂 BPMN 流程设计。
- 不允许老师修改前台视觉布局。
- 不让字段直接控制 CSS、组件位置、动画样式。

这些能力虽然听起来强，但会明显增加系统复杂度，也容易破坏现在已经形成的展示风格。

## 5. 模板类型设计

低代码模板应围绕当前已经固定的专题资料类型展开。

建议内置模板：

| 模板 | 对应 content_type | 适用板块 |
|---|---|---|
| 专题概况 | article | 专题概况 |
| 专业群布局 | article | 专业群布局 |
| 实训场景 | scene | 实训场景 |
| 产教协同 | activity | 产教协同 |
| 名师名匠 | person | 名师名匠 |
| 优秀校友 | person | 优秀校友 |
| 优秀学生 | person | 优秀学生 |
| 专题成果 | achievement | 专题成果 |
| 技能大赛 | activity | 技能大赛 |
| 荣誉资质 | honor | 荣誉资质 |
| 视频资源 | video | 视频资源 |

这些模板不改变前台，只决定后台怎么收集资料。

## 6. 字段控件设计

第一阶段建议支持以下控件：

| 控件 | 用途 |
|---|---|
| 单行文本 | 姓名、标题、单位、职务、获奖名称 |
| 多行文本 | 简介、事迹、项目说明 |
| 富文本 | 较复杂正文 |
| 数字 | 年份、数量、排序 |
| 日期 | 活动日期、获奖日期 |
| 下拉选择 | 所属板块、资料类型、状态 |
| 单选/多选 | 标签、荣誉类别 |
| 图片上传 | 人物照、封面图、现场图、证书图 |
| 视频上传/视频地址 | 视频资源 |
| 文件上传 | 附件、证明材料 |
| 开关 | 是否重点展示、是否启用 |

字段配置项：

- 字段名称
- 字段编码
- 控件类型
- 是否必填
- 默认值
- 占位提示
- 校验规则
- 排序
- 是否显示在卡片摘要
- 是否进入抽屉详情
- 映射目标

## 7. 数据映射规则

低代码表单最终仍然映射为现有结构化资料。

### 7.1 基础字段映射

| 表单字段 | content_item 字段 |
|---|---|
| 标题 | title |
| 副标题 | subtitle |
| 摘要 | summary |
| 正文段落 | body_json |
| 类型字段 | meta_json |
| 图片/视频 | content_item_assets |
| 所属板块 | module_key |
| 资料类型 | content_type |
| 排序 | sort_order |
| 是否重点展示 | featured |
| 是否启用 | enabled |

### 7.2 图片角色映射

| 图片用途 | asset role |
|---|---|
| 封面图 | cover |
| 人物照片 | portrait |
| 荣誉证书 | certificate |
| 活动现场图 | gallery |
| 视频资源 | video |

前台根据 `content_type` 和图片角色自动决定排版，不由老师手动设计。

## 8. 后台交互方案

### 8.1 管理员视角

管理员进入“资料采集模板”模块，可以：

- 新建模板。
- 从内置模板复制。
- 调整字段顺序。
- 设置字段是否必填。
- 设置字段映射。
- 设置模板适用的门户类型和板块。
- 启用/停用模板。

建议后台操作流程：

```text
选择模板类型
  → 配置字段
  → 配置映射
  → 预览老师填写效果
  → 保存启用
```

### 8.2 老师视角

老师不需要理解低代码，只需要：

- 选择负责的门户。
- 选择资料板块。
- 选择资料模板。
- 按表单填写内容。
- 上传图片/视频。
- 提交审核。

老师看到的是“规范化资料录入表”，而不是复杂的设计器。

## 9. 前台展示策略

前台保持现有展示逻辑：

- 学校门户不变。
- 系部门户不变。
- 专题页无缝循环滚动不变。
- 抽屉详情页不变。
- 顶部栏不变。
- 图片继续按原比例自适应显示。
- 多图继续轮播。

低代码模板只影响内容来源，不影响视觉表现。

前台仍按以下类型自动展示：

- `article`：普通图文
- `person`：人物照 + 介绍
- `activity`：活动说明 + 图片轮播
- `honor`：证书/荣誉图优先
- `achievement`：成果摘要 + 图文
- `scene`：场景图片 + 说明
- `video`：视频封面/播放器

## 11. 实施阶段

### 第一阶段：模板配置和动态表单

目标：后台能创建模板，老师能按模板填写资料。

内容：

- 新增模板管理页面。
- 新增字段配置功能。
- 新增动态表单渲染。
- 表单数据保存为 `lowcode_records`。

风险：低。

### 第二阶段：映射结构化资料

目标：表单提交后自动生成现有 `content_item`。

内容：

- 配置字段映射。
- 保存时生成 `body_json`、`meta_json`、`assets`。
- 接入现有审核流程。
- 前台自动显示。

风险：中。

### 第三阶段：模板复制与版本管理

目标：模板可以复用、回滚、升级。

内容：

- 模板复制。
- 模板版本。
- 已发布模板保护。
- 记录保留填写时的模板版本。

风险：中。

### 第四阶段：体验增强

目标：让老师更容易填写。

内容：

- 字段分组。
- 图片批量上传。
- 自动摘要。
- 表单预览。
- 从已有资料生成模板记录。

风险：中。

## 12. 风险控制

### 12.1 视觉风险

风险：低代码能力破坏前台统一设计。

控制方式：

- 前台不开放布局设计。
- 后台只配置字段和映射。
- 前台仍走固定模板。

### 12.2 数据风险

风险：新表单数据和旧结构化资料不一致。

控制方式：

- `content_items` 仍是前台展示主数据。
- `lowcode_records` 作为填写源数据。
- 保存时同步生成或更新 `content_item`。

### 12.3 使用风险

风险：老师不会配置复杂模板。

控制方式：

- 老师只填写，不设计。
- 模板设计只给管理员。
- 内置常用模板。

### 12.4 工程风险

风险：一次性改造过大。

控制方式：

- 先做资料模板，不做平台级低代码。
- 先绑定专题资料，不扩展太多业务。
- 保留旧版结构化资料录入入口。

## 13. 推荐结论

推荐采用“后台低代码资料模板 + 前台固定展示模板”的路线。

这条路线的优点：

- 能满足低代码快速开发业务功能的要求。
- 不破坏当前已经完成的前端展示效果。
- 能复用现有 `content_items`、审核、素材、专题抽屉。
- 改造范围可控。
- 后续可以逐步扩展到更多业务表单。

一句话总结：

> 低代码负责让后台资料更好填，前台继续负责把资料展示得好看。
